# 验收报告（C04 骨架）

**结论先行**：接口回归和备份恢复演练能自动出证据；**生成可用性、检查有效性、真实文件交付三块必须由业务人员用脱敏真实项目复核，构造用例 PASS 不能替代业务验收**。本报告只给结构和自动证据，凡是没人复核过的一律留空并标「待业务验收」，不填推测值、不把自测当准确率。

自动回归命令：`python -m backend.eval.test_reliability`（退出码 0 才算通过，断言数见运行输出）。

### 1.1 真实样本机器验收（**仍非业务验收**）

> 这一节由使用者用自己的脱敏真实招标文件填。建议一次性临时库 + `demo` 模式跑（零模型费用），全程只读源文件。

| 项 | 记录 |
| --- | --- |
| 文件类型 / 体积 / 页数 | 待填 |
| 解析结果（有效字数 / 状态 / 需人工确认项） | 待填 |
| 要求表条数（硬性 / 废标 / 评分） | 待填 |
| 目录章节数（protected / structured / narrative） | 待填 |
| 是否有可对照的旧标书 / 评标结果 | 待填 |

**先把「有几组样本」说清楚**：同一采购项目的多个标包、多份附件，共用同一份主招标文件时，**只是 1 组样本**，不能拿来凑「5—10 组独立项目样本」。没有旧标书或评标结果，就没有可对照的标准答案，不得编造准确率。

**这一节只证明**：链路在真实文件上能跑通，确定性规则的行为符合设计。**不证明**生成内容正确、要求没漏、事实没错、文件可投。`demo` 模式的模板稿不能作为投标依据。

用真实项目的最终 Word / 分册包，按目标投标平台要求核对：目录域刷新、分册归属、附件清单、签章、格式与上传限制。

| 结论项 | 结果 |
| --- | --- |
| 最终 Word 可正常打开、目录页码正确 | 待业务验收 |

**已写明的能力边界，不能当成已实现**：目录域由 Word 打开时更新，本系统不刷新域结果；PDF 转换与电子投标客户端专用格式未实现；图片 / 嵌入对象里的文字、盖章、水印无法自动识别，须人工逐项核对；未登记项目暗标规则时扫描结论不构成完全暗标合规证明。

## 5. 恢复结果（可自动取证）

```bat
python -m backend.ops.backup create --out D:\backups
python -m backend.ops.backup verify D:\backups\bidagent-backup-YYYYmmdd-HHMMSS.zip
python -m backend.ops.backup drill  D:\backups\bidagent-backup-YYYYmmdd-HHMMSS.zip --report docs\恢复演练结果.json
python -m backend.ops.backup restore D:\backups\bidagent-backup-YYYYmmdd-HHMMSS.zip --target D:\restore-test
```

- 备份覆盖：业务库（含各企业分库）、`auth.db` 账号 / 组织 / 会话、原件、上传件、导出产物、模型与策略配置、项目根 `.env`。
- 数据库用 SQLite Online Backup API 取一致性快照，不直接 copy WAL 未落盘的半截库；`-wal` / `-shm` / 临时文件不进包。
- `drill` 在系统临时目录做隔离恢复 → 逐文件核对 sha256 → 打开每个库跑 `PRAGMA integrity_check` 与表行数对账 → 跑完删除，不碰生产数据。
- `restore` 只写空目录，**拒绝**写回生产数据目录及其上下级，也不覆盖目标里已有的库。切换流量由管理员手工决定。

| 项 | 结果 |
| --- | --- |
| 最近一次 `drill` 结论 | 运行后把 `docs\恢复演练结果.json` 归档于此 |
| 备份包异地存放 / 密钥保管 | 待管理员确认（备份内含密钥，按密钥管理存放） |
| 真实故障场景的恢复时限 | 待运维测量 |

## 需要用户提供的输入（AI 不能代做）

1. 5—10 组**相互独立**的脱敏真实项目 / 旧标书与评标结果，明确可覆盖范围。
2. 至少一名未参与开发的业务人员做独立复核，并填上面两张表。
3. 一名未参与开发的用户实际完成一次起草或旧标书复查，记录卡点原文。
4. 目标投标平台的格式与递交要求（是否要 PDF、是否要客户端专用格式、分册命名规则）。
5. 备份包异地存放位置与密钥保管责任人。

## 延后项（功能稳定后再做，不列为本次完成）

- 拆分前端模块、优化检索、大文件任务专项优化。
- 是否把 SQLite 换成独立数据库、单进程任务队列换成跨进程队列：**用测得的排队时间 / 并发数据决定**，不凭感觉升级。
- 当前写互斥与 `JOB_POOL` 任务队列仍是**单进程内**的锁 / 单 Worker；多进程部署前必须先做跨进程任务认领与锁，否则同项目可能并发写。导出确认令牌已落企业库、合规台账已加跨进程锁，但这两项不等于任务队列可水平扩容。

## 不能据此宣称

不能宣称「准确率已达某数值」「完全暗标合规」「支持所有投标平台格式」「已通过业务验收」。以上结论只有在上表全部由真实样本与业务人员填完、且第 4 项平台递交成功后才能给出。
