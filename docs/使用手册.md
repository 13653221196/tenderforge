# 标书智能体 · 使用手册

> 适用版本：2026-11-11 当前版本（本地/服务器部署通用）
> 面向：企业标书编写人员、复核人员、企业管理员
> 配套文档：`docs/安装部署.md`（安装与部署）、`web/manual.html`（系统内「帮助」按钮打开的同款在线手册）

**一句话流程**：上传招标文件 → 核对解析结果 → 定目录 → 写正文 → 看「能不能交」 → 导出 Word。

---

## 0. 先记住这三条，比操作更重要

1. **没接模型时生成的是「模板稿」，不能拿去投标。** 系统会把整本结论判成红色并写明「演示模式 / 模板稿」，也不会把它说成可交付。要生成真实内容，先由管理员在「设置」里配置并测通模型。
2. **导出前的提醒不会禁止下载。** 这是本产品既定规则：提醒 + 一次性「我已知情」令牌仍可下载。所有提醒都会随导出记录留痕，但**提交前必须逐项人工复核**，系统不代替人签字。
3. **系统不保证中标，也不等于已通过业务验收。** 它做三件事：不漏项、给证据、留痕迹。机器回归和真实文件实测只证明链路跑得通，生成质量、要求漏报、事实错误、废标率都要业务人员独立复核。

## 1. 一分钟上手

| 步骤 | 在哪 | 做什么 |
|---|---|---|
| 1 | 登录页 | 用管理员给的账号登录，首次登录立刻改密码 |
| 2 | 「开始」 | 新建项目，填项目名称 |
| 3 | 「资料」 | 上传招标文件（Word/PDF/Excel），看「解析待核对」提示 |
| 4 | 「资料」 | 展开「招标解读汇总」，确认要求、评分、清单、限价有没有抽全 |
| 5 | 「标书正文」 | 确认目录 → 点「一键写整本」，或逐章写 |
| 6 | 「检查与交付」 | 看「能不能交」卡，按提醒改 |
| 7 | 「检查与交付」 | 导出 Word，下载后人工逐页复核再递交 |

主界面只有 **4 个页签：开始 / 资料 / 标书正文 / 检查与交付**。知识库、招标要求表、进度与下一步在右上角「管理」菜单里；运行记录、用量与审计、设置只有企业管理员可见。一线写标员不需要进配置台。

## 2. 登录与账号

- **初始管理员**：全新部署时系统自动创建账号 `admin`，随机密码写在服务器 `data/初始管理员.txt`。**首次登录后立即修改密码**，并妥善删除或保管该文件。
- **自助注册默认关闭**，只有企业管理员能建账号；开启需运维在服务器设 `BIDAGENT_ALLOW_SIGNUP=1`（公网部署不建议开）。
- **忘记密码**：请企业管理员在「设置 → 企业与成员」里重置；密码至少 8 位。
- 登录状态保存在浏览器 Cookie 中，退出登录会立即失效。

### 企业管理员能做什么

建成员账号、改密码、配模型与 API Key、看用量与审计、看运行记录、设置隐私与预算策略、管理企业配置归属。

### 成员能做什么

按项目角色授权。旧项目没有成员名册时，同企业账号默认可编辑；**一旦添加第一个成员，立刻切换为按名单授权**，不在名册里的同企业账号连查看和下载都会被拒。只读人员不能改正文也不能下载；复核人员可标记复核但不能写正文；归档、删除、收录进知识库、恢复快照、改名册只有负责人或管理员能做。

---

## 3. 新建项目

一个投标项目建一个项目，不同项目的资料、正文、检查结论互相隔离。项目可归档（从侧栏收起、数据保留，不删除），也可收录进企业知识库作为范例。

> 上传前请先确认：这份招标文件是本次要投的那一份。补遗、澄清、修改版用「招标文件版本链」追加，旧版条款不会被静默丢掉。

## 4. 上传资料与解析核对

### 支持什么

Word（.docx）、PDF（.pdf）、Excel（.xls/.xlsx）、文本（.txt/.md）等。**单份文件上限 20MB**（按有效载荷算），超限会明确报错并提示拆分，不会静默截断。压缩包（.zip）和签名文件（.sign）不是招标文件正文，会被如实拒收；请先解压出里面的 Word/PDF 再传。

### 「解析待核对」是什么

含扫描页、内嵌图片或识别不全的文件会标 `needs_review`，**在人工确认前不进入事实依据池**——这是防止把没看清的内容当成招标要求。

- 展开提示可看到未识别页、以及**内嵌图片里 OCR 出来的文字**。
- **图片文字只供你对照原件核对，绝不并入正文**。二维码、系统截图里的字若混进正文，会污染按章检索和要求抽取。
- 确认方式：对照原件看图片里确实没有遗漏的招标要求，再点「我对照原件核对过了」。不确认就写正文，系统会一直把这份文件挡在依据外。

### 在对话框里上传：跟着你那句话一起发

对话框点「上传文件」后，**文件解析期间「发送」按钮会置灰**（显示「解析中…」），输入框上方出现「正在上传解析」提示条；这期间仍可以先把要问的话写好，不会打断打字。**解析成功后按钮自动开放**，文件以「待发送附件」小条挂在**输入框里**（不是聊天消息），不会立刻入库，也不会单独记一条「[上传文件]」的对话。光标会回到输入框，直接打字写清它用来做什么，再点「发送」，问题与文件一起提交：**服务端先按用途把文件确定性入库，再按你这句话执行后面的步骤**（解读、体检、写作等）。用途按「你手动指定的 > 你的话 > 文件名与正文特征」判断，聊天记录里只留你打的字。

**一次发送就够**：入库是服务端的固定步骤，不交给模型临时决定，也不会因为「帮我分析一下」这类简短指令反问卡住你。用途实在判不准时，文件会按最保守的「我提供的资料」入库并在回复里说明，不会被错当成招标要求或标书正文；想改用途可在附件小条里展开「手动指定（可选）」，**发送前**选好即可。

**只有服务端确认入库后，附件小条才会消失**，并显示「本次对话已入库」，之后可以**继续打字、继续发送**，资料已在库里，不必重复上传。以下几种情况文件**不会消失**：没解析出有效文字、入库出错、网络异常 / 服务没响应 / 登录过期、刷新页面或重新登录。附件小条会写明真实原因，你刚打的那句话也留在输入框，直接点「发送」重试即可，不用重新选择文件、也不用重新解析。同一项目未发送的附件按浏览器会话保留，关掉标签页才清除。

资料页、正文页、知识库页的「上传招标文件 / 上传文件当资料 / 上传标书文件」等按钮用途已经明确，仍是选完文件即按该用途导入，不受此改动影响。

### 招标文件版本链

补遗/澄清上传后形成版本链，新旧条款都保留，可回看哪一版说了什么。不要直接删旧文件重建项目。

## 5. 招标解读汇总（资料页折叠卡）

「资料」页有一个**默认收起**的「招标解读汇总」卡，展开时才计算（大文件约 1 秒内），不拖慢首屏。它把原本散在各处的确定性结果聚成一张可核对的卡：

| 区块 | 内容 |
|---|---|
| 招标要求 | 硬性 / 废标 / 评分各多少条，总数多少 |
| 评分要素 | 总条数报全量，明细只预览前几条，避免一屏刷满 |
| 货物清单 | 抽到多少行、是否缺数量 |
| 最高限价 | 「无 / 有金额 / 含糊 / 未提及」四态 |
| 报价核对 | 是否超限、多来源总价是否一致；没读到报价表就写「均未校验」 |
| 证照状态 | 过期 / 临期 / 日期写错各多少 |
| 待核对资料 | 哪些文件还卡在 `needs_review` |
| 招标要素 | 22 项决策要素（保证金、开标时间、付款方式、质保期、合同条款等），只从原文切片，没识别就写「未识别」 |
| ★▲ 参数 | 带 ★ / ▲ 的原文行单独成表，与货物清单分开列，两边数字不串 |
| 按章重点 | 按章节标题列出本章该重点核对的维度，默认折叠 |

**这张卡不是已确认事实**，卡上会写明「仍须对照原件核对」。它的用途是让你不用翻原文就能发现「哪一块没抽到」，而不是代替你确认条款。空项目会如实说没有招标原文，不补示例数字。

### 企业资产台账与得分材料反查

「资料」页另有**默认收起**的「企业资产台账」卡：按**资质证照 / 人员证书 / 业绩证明 / 检测报告 / 获奖荣誉**五类登记企业资产，可填持证主体、证书编号、有效期、原件位置，并标记「已对照原件核验」。资产属于企业、跨项目复用，不会绑在某一本标书上；原有的企业事实与项目资料一条都不迁移，只是并列读进证照体检。

有效期沿用证照的五态判定（已过期 / 即将到期 / 有效 / 日期写错 / 未填）。过期资产会进导出提醒，也会在「能不能交」卡上提示；**仍然是提醒，知情令牌仍可下载**，不是禁止下载。

「能不能交」卡还会多一行**得分材料反查**：把评分 / 硬性条款与本企业资产做确定性对照，点「查看缺件清单」看「哪条条款可能需要什么材料、现在有没有」。它只列**候选材料**，不判定「能得几分」，也不因为没匹配到关键词就说这条条款不需要材料；请对照评分办法与原件逐条人工确认。

## 6. 招标要求表与逐条响应

「管理 → 招标要求表」是从招标原文抽出的要求清单，按**硬性要求 / 废标条款 / 评分要素**分类，可逐条查看来源、人工增删与停用。

- 每条要求保留出处（文档、页码、字符区间），可回跳原文核对。
- 误抽的大项/小项可删除，删错了用「恢复被删要求」找回。
- 逐条响应矩阵把「招标要求 → 我方响应 → 依据材料」放在一起，方便复核。

---

## 7. 货物清单与最高限价

「资料」页另有**默认收起**的货物清单卡，展示前若干行预览：物资名称、规格、单位、数量、分包、交货期。

- 抽不到清单会如实说没识别到表头，不编行数。
- **数量缺失会进导出提醒**（漏数量是常见废标点）。
- 最高限价只给四态结论。写「本项目无最高限价」就是「无」，不会被误读成金额；条款含糊时只提示人工核对，**不代替评审口径判定超限**。
- 报价核对只看算术事实：限价金额与投标总价比大小、投标函/开标一览表/中文大写/多张报价表合计之间是否一致。结论里会写明含税价、单价限价、分包限价、角分剔除**仍须按评审口径人工复核**。

> 真实国网文件实测中，★/▲ 类标记出现 0 次、`*` 全是乘号或尺寸，货物清单也没有预算列。系统**不会把 `*` 当成强制参数、不会编造预算列**；若招标文件确实带 ★/▲，会抽成独立的「★▲ 强制技术参数」表，只列原文行、不自动判定是否实质性响应，仍需对照评分办法人工核对。

## 8. 知识库

「管理 → 知识库」分两类：

- **范例（sample）**：写好的旧标书，整本粘进来会自动按标题拆章，可作为写作参照。复用范例会标注核验状态，不把旧项目内容当成已确认事实。
- **通用素材（material）**：企业资质、业绩、方案段落等。

新增/编辑素材时可**选填「有效期」**（证照类建议填）。卡片会显示状态标：

| 状态 | 含义 |
|---|---|
| 已过期 | 高风险，进导出提醒，也进「能不能交」卡提示 |
| 即将到期 | 60 天内，中等提醒 |
| 有效 | 正常 |
| 日期写错 | 提示按 `YYYY-MM-DD` 修正 |

系统**不会 OCR 证书上的日期**，也不会给没填有效期的素材报警——避免误判和噪音。过期证照不会被自动删除或禁用，只是提醒。

## 9. 定目录

「标书正文」页空项目时有三种起点（按招标格式目录 / 按评分办法 / 从零开始），可手动加章、改名、删章、微调。

目录上带三类标记，决定这一章怎么写：

| 类型 | 典型章节 | 行为 |
|---|---|---|
| `protected` 保护章节 | 投标函、报价表、资格声明 | **不走自由生成**，只给待人工核验清单，防止模型编造资格承诺 |
| `structured` 结构化 | 商务响应、偏差表、资格响应 | **不调模型**，只出「招标要求 → 响应材料 → 待人工核验」 |
| `narrative` 叙述 | 技术方案、实施方案 | 由模型按本章检索到的招标条款撰写 |

目录会带分册、字数预算、评分项标注；评分项多的章节会单独成章，方便按分值分配篇幅。

### 目录确认闸门（写正文前必须做一次）

目录区右上角有「确认目录」按钮。核对好章节名称与顺序后点它，目录区显示「已确认」，这之后才能写正文。

- 未确认时点「一键写整本」「AI 生成本章」「按资料改写」，或在对话里说「写整本标书」，都会被拦下并提示先确认目录，避免目录不对整本返工。
- 改章节名、加章、删章、上下移、重新生成大纲、套用旧目录、导入已有标书，都会让确认**立即失效**，需要重新确认。
- 章节行右侧（鼠标悬停时出现）有 ↑ ↓ 可微调顺序；只换顺序，正文、版本与依据都跟着同一章走。
- 升级前已经写过正文的老项目会自动视为已确认，不会被这次改动锁死。

## 10. 写正文

- **先确认目录**：见第 9 节。目录没确认时，整本与单章生成都会被拦下；确认只需点一次，改动目录后要重新确认。
- **一键写整本**：按目录顺序跑，期间可看进度；任务显示「部分完成」时，已完成章节不会被覆盖，人工改过的稿子会被保留。
- **按章生成 / 手动改写**：右侧工具栏提供改写、续写、保存。生成期间你若改了这一章，系统以你的人工稿为准。
- **取消整本**：可取消，已完成的章节保留，未跑的不再跑。
- **服务重启**：长任务状态会在库里留痕，但重启后不会自动续跑未完成章节；请在重新登录后确认进度再继续。
- 演示模式（未接模型）产出的是模板稿，正文里会保留 `XXX / 待补充 / 需补充` 等占位符，**不会被导出清理抹掉**——它们要交给检查规则拦下，而不是藏起来。

## 11. 检查与「能不能交」

「检查与交付」页顶部是**能不能交**卡，把质量、体检、门禁、生成模式四套结论合成一句话，三态：

- **红灯**：不能交（例如演示模板稿、有硬性否决项、体检没跑完）
- **黄灯**：还有必须先处理的事
- **绿灯**：机器检查层面没有阻断项 —— **仍不等于可以直接投标**

卡上还会**直接显示过期/临期证照提示**（以前只在导出时才看到，太晚）。证照扫描没跑完会如实说「没查成」，不静默当作没风险。

整本自动体检覆盖 8 项：质量、章节、逐条响应、雷同、模拟评标、事实、引用、合规。**「体检查完」不等于「可交付」**，系统刻意区分这两个口径。

「能不能交」卡还会显示**得分材料反查**的一行提示（缺 N 项材料候选），点「查看缺件清单」展开完整对照。它只是候选清单，**不改变红 / 黄 / 绿灯的判定口径，也不禁止下载**。

## 12. 导出 Word

### 导出前的提醒卡

真实招标文件常一次给出上百条提醒，系统会聚成：**一句结论 + 最多几条跨类重点 + 按类别折叠的全量明细**。一条都不会省略，可逐条展开确认。

提醒按评审后果分四级，让你一眼看清后果：

| 级别 | 含义 |
|---|---|
| 硬性否决 | 可能导致废标，优先处理 |
| 硬性扣分 | 会影响得分 |
| 加分项 | **系统恒为 0**，并明写「系统不自动判定加分机会」，不硬凑一类骗人 |
| 参考项 | 建议核对，不直接影响结论 |

### 知情令牌

点下载时按既定规则：看提醒 → 确认「我已知情」→ 仍可下载。这个令牌一次性、用完即失效，导出记录会留痕。**它不是「符合检查」的证明**。

### 导出后

- 产出文件与版本在「产出文件」里可回看，含 Word、检查报告、分册与投标包。
- 最终文件检查会扫占位符、空章、目录、暗标项；**导出清理只删系统自述句，不会删掉真实占位符**。
- 暗标检查覆盖标题、正文、表格、页眉页脚、文档属性、嵌入对象；**图片里的文字、盖章、水印、修改历史无法自动识别，须人工逐项核对**。
- 最终 Word 的目录域、分册、签章、平台递交仍须人工完成。

## 13. 模型、隐私与多企业

- 管理员在「设置」里选模型、填 API Key、测连通性。密钥只写服务器本地 `data/`，接口返回一律脱敏。
- 「管理多个模型」里可按环节分工：**智能体规划 / 对话回答**用快模型省钱，**写标书 / 改写**与**验标书 / 复核**用强模型；不单独指定就跟随「当前模型」。基座里的 AI 判定（AI 复核、否决条款、偏离表、模拟评标、润色、可研）与 AI 技能跟随**「验标书 / 复核」环节**绑定的模型；该环节没绑定或模型没配全时回落到当前模型。想分服务商只需登记另一家模型再绑到某个环节，不必改部署或增加界面操作。
- 关闭联网后不再调用外部模型，内容零外发；身份证、银行账号、手机号自动打码，报价表、投标函、资质章节正文不外发。
- 项目数据按企业物理分库；模型、密钥、预算、隐私、策略、运行状态按企业各存一份。**模型与密钥绝不跨企业继承或复制**。「设置 → 配置归属」会逐项标明来源。
- **语义检索开关（可选，默认关闭）**：管理员在「设置 → 其他设置 → 语义检索开关」里展开，填百炼 API Key、勾选启用，建议先点「测通」再保存。开启后，招标文件与知识库里换了一种说法的条款也能被找到；关闭时完全按字面检索，零费用、零外发。密钥按企业单独保存，接口返回脱敏。演示模式、数据出域未确认、预算用尽或接口失败会自动退回字面检索，无需人工干预。语义召回但字面不命中的片段会标「须人工核对」，**不能当数值、资质或承诺的依据**，请回原文确认后再用。
- 同一招标项目被多家企业投标时，平台只记招标正文指纹，不读别家正文，并会把这种情形列为导出重点提醒。

## 14. 备份

在服务器项目根用**同一个 Python 解释器**执行：

```bash
python -m backend.ops.backup create --out /srv/backups
python -m backend.ops.backup verify /srv/backups/备份包.zip
python -m backend.ops.backup drill /srv/backups/备份包.zip --report /srv/backups/drill.json
```

备份包覆盖业务库（含各企业分库）、账号库、原件、上传件、导出产物、模型与策略配置、`.env`，用 SQLite 一致性快照，**不是直接复制 .db**（WAL 里未落盘的写入不会漏）。`restore` 只写空目录，写回生产目录或覆盖已有库会被拒绝。

> 备份包含模型密钥和账号数据，按密钥管理存放，不要外发。备份能读回 ≠ 业务验收通过。

## 15. 常见问题

| 现象 | 原因 / 怎么办 |
|---|---|
| 说「验一下标书」却让我先上传 | 空项目空跑会得到「0 个问题」的假结论，系统改为提示先上传 |
| 只传了招标文件，还提示「缺标书正文」 | 废标风险要两边对照；只有一边时结论只覆盖那一半，并会在开头注明 |
| 点「一键写整本」没反应 | 先看目录是否有章、**是否已点「确认目录」**、模型是否测通、是否有正在跑的任务；任务状态在「检查与交付」 |
| 提示「目录还没确认」 | 这是目录确认闸门：在目录区点一次「确认目录」即可；改过章节名 / 顺序后要重新确认 |
| 生成很慢 / 中途停了 | 整本生成是长任务，按章推进；看进度，已完成章节不会丢 |
| 双击启动文件闪一下就没了 | 自检没过；在命令行跑 `python -m backend.app.preflight` 看具体项和「怎么办」 |
| 数据目录和端口在哪里改 | 项目根 `.env`（`BIDAGENT_DATA` / `BIDAGENT_HOST` / `BIDAGENT_PORT`），自检、启动脚本、服务三处共用同一份 |
| 上传报「文件超过 20MB」 | 拆分文件；服务器部署还需把 nginx `client_max_body_size` 调到 25m 以上 |
| 图片里的字没进正文 | 这是**故意的**：内嵌图片文字只放在「解析待核对」里供人工看，不进检索与依据池 |

## 16. 验收边界与还不能做的事

- 以下项目**必须由业务人员自行验收**，机器结果不能替代：要求漏报/误报、事实错误与无依据承诺、人工修改量、暗标图片盖章水印识别、最终 Word 目录域/分册/签章/平台递交、废标率与中标结果。
- 机器验证只证明链路跑得通，不等于业务准确率。也没有现成的「标准答案」可以用来衡量准确率——真实招标场景里，正确与否往往要等评标结果。
- 演示模式模板稿**不能作为投标依据**。要验生成质量，需管理员配置真实模型、明确同意模型费用，并由人逐章复核。
- 目录确认闸门、企业资产台账、得分材料反查、招标要素维度已落地；**投标结果复盘回流、暗标图片 / 水印自动识别、法规规则中心（含官方法条自动同步）** 仍未做，如实列为人工项或后续批次。

## 17. 生成输入与逐要求支撑（2026-11-14）

在“标书正文”选择章节，点击“来源与历史”，可查看当前稿对应的生成尝试、实际输入和历史来源片段。输入来源表示模型确实看过的材料；它不自动证明正文成立。范例只参考写法，语义召回保持候选；无法定位的输入块不提供虚构原文坐标。部分截断及原文变化会明确显示。

在“管理 → 招标要求表 → 逐条响应矩阵”核对每一条要求：

1. 点击“核对本条事实 / 证据 / 附件”，选择要求类型。资格、人员、业绩、参数或承诺需填写对应主体、字段、单位及适用范围；有有效期的证明还需开标或评审日期。
2. 选择本项目事实、原文证据或附件，填写关联理由，分别登记候选、支持或冲突。“生成候选关联”只提供词面建议，不替你确认。错误关系可解除。
3. 原件类先建立有效附件关联，再核对实际原件字段和签章，勾选后保存类型核对。替换附件或改关联后须重新核验；旧勾选不能沿用。
4. 缺口清单全部处理后，再点击“人工确认已落实”。照抄条款、缺有效证明、对象归属错误或材料变化均不能凭点击确认绕过。不适用需写理由并记录责任人。

确认对应具体版本。正文、要求、关联事实、证明原文或附件变化后，该条返回待复核；无关材料不会使其他已确认要求全部失效。导出时会再次核对附件内容，即使文件在系统外被替换，也不能复用旧导出确认。

历史证据与生成记录会保留。人工改稿后来源标待复核；恢复正文时仅恢复匹配历史关联，没有记录则显示来源未知。段落优化不能可靠确定影响范围时，旧证据保留并待复核。

旧项目没有版本指纹的“已确认 / 不适用”将在迁移后进入待复核，旧正文和原复核信息保留。查看需要项目权限；建立、解除关系及类型核对需要项目负责人、复核人或企业管理员权限。企业间实际输入记录和关联不共享。

原件自动打开检查支持 PDF、DOCX/XLSX/PPTX、ZIP、常见图片及 UTF-8 文本。损坏容器、空文件和未知格式保持缺口，需要补充可核验文件。系统不能代替责任人判断真实签章和业务适用性。

*本手册描述的是当前版本的实际行为。系统内“帮助”按钮打开 `web/manual.html` 在线手册；工程验证与真实业务验收的边界见第 16 节。*
