标书智能体 · 使用手册

一句话流程：上传招标文件 → 定目录 → 逐章写正文 → 检查改好 → 下载 Word。全部数据留在本机，按企业隔离。

1. 一分钟上手

第一次用，只做这五步就够了；做完就是一份能交的标书初稿。

主界面只有四个页签：开始 / 资料 / 标书正文 / 检查与交付。知识库、招标要求表、进度与下一步在右上角「管理」菜单里；运行记录、用量与审计、设置只有企业管理员能看到。一线写标员不用进配置台。
第 1 步上传招标文件
第 2 步确认章节目录
第 3 步一键写正文
第 4 步检查并改好
第 5 步下载 Word
  1. 登录后进入「开始」页，点顶部引导里的上传招标文件，把招标书 PDF / Word 传上去（一次一个文件；多个附件请分次上传）。
  2. 到「标书正文」页，直接点生成目录（系统按招标文件的评分项和硬性要求排章节）。要照旧标书、旧项目目录或手动建章，展开下面的「其他起步方式」再选。
  3. 点右上角一键写整本。左侧目录会逐章变绿，写完自动停在第一章。
  4. 逐章翻一遍，哪章不满意就在右侧点AI 生成本章或写一句改写要求再点按资料改写。改完自动保存。
  5. 到「检查与交付」点开始检查，先看最上面那张能不能交卡：红色先去改正文，黄色要确认风险，绿色才下载。要改的问题点采纳，再点按采纳的问题改好并复查；点卡上的下载 Word（或回正文页下载）即可。
不确定做什么的时候，回「开始」页问一句人话就行，例如「根据我上传的资料写第二章」；右上角「进度与下一步」会告诉你当前还差什么。
在对话框点「上传文件」后，解析期间「发送」按钮会置灰（显示「解析中…」），输入框上方出现解析提示条；可以先写好要问的话。解析成功后按钮自动开放，文件会以「待发送附件」小条挂在输入框里（不会变成一条聊天消息，也不会立刻入库）。光标会回到输入框，直接打字写一句它用来做什么（例如「这是招标文件，请解读并生成标书」）再点发送——服务端先按用途把文件确定性入库，再按你这句话执行解读 / 体检 / 写作等步骤；一次发送就够，不会因话短就反问卡住。用途判不准时按最保守的「我提供的资料」入库并说明，发送前也可在小条里展开「手动指定」选好用途。聊天记录只留你打的字。只有服务端确认入库后小条才消失；没解析出有效文字、入库出错、断网 / 服务没响应 / 登录过期、刷新页面时，文件都会留在输入框并写明真实原因，原话也在，直接点发送重试即可，不用重新选文件。入库后可以继续打字、继续发送，资料已在库里不用重复上传。资料页等用途明确的上传按钮仍是选完文件即导入。

数据存在哪里

  • 存在运行服务的这台机器上，不是存在浏览器里。数据库、上传的文件、导出的 Word 都在安装目录的 data/ 下，每个企业一个独立库。
  • 本机部署：数据就在你自己电脑上，关掉浏览器不会丢，换浏览器登录同一个账号也能看到。
  • 公司服务器部署：数据在服务器上，同事的浏览器只是访问它；备份要备份服务器上的 data/，备份浏览器没有意义。
  • 要换存储位置（比如放到 D 盘或网络盘），设置环境变量 BIDAGENT_DATA 指向目标目录再启动，主程序和基座会一起改过去。
本工具是辅助起草、检查、人工复核后导出：正文、报价、承诺、资格证明都必须由业务人员逐项核对盖章后使用，不能当作自动投标或自动定标工具。

2. 登录与账号

登录

浏览器打开系统地址，进入登录页，输入账号和密码。登录状态保存在浏览器里，关掉再打开一般不用重新登录。

初始管理员

项目说明
账号admin
初始密码由部署人提供，写在部署目录的 data/初始管理员.txt 里（该文件请勿外发）
所属企业默认企业（企业管理员）
第一次登录请立刻改密码：右上角头像 →「企业与成员」→ 在成员列表里给自己点「重置密码」。改完可以把 data/初始管理员.txt 删掉，删掉后不会再生成。

忘记密码 / 换密码

  • 自己改：头像菜单 →「企业与成员」→ 找到自己 → 重置密码。
  • 忘了密码：找本企业的管理员重置；管理员也忘了，需要运维在服务器上重置数据库记录。
  • 退出：头像菜单 →「退出登录」。

3. 企业与成员

一个企业 = 一套独立的数据库。不同企业的项目、资料、知识库、用量互相看不到，接口层也会拦。

管理员能做什么

  • 开账号：「企业与成员」→「新增成员」，填账号、姓名、初始密码，角色选「成员」。
  • 改角色：成员 ↔ 管理员。管理员能改模型与策略设置、能管成员。
  • 重置密码 / 停用 / 删除：停用后不能登录但数据保留；删除是移出本企业。
  • 改企业名：页面顶部填写企业名称后保存，只影响显示。

成员能做什么

成员可以正常做标书（建项目、传资料、写正文、检查、导出），但看不到也改不了模型接入、策略开关、成员管理这些平台级设置。

给同事开号时建议一人一号，不要共用 admin：用量与审计里能看到每个人做了什么。

4. 项目

一个招标项目建一个项目。项目是资料的容器，也是正文和检查结果的归属。

  1. 左侧「投标项目」上方点新建项目，填项目名（建议写「年份 + 项目简称」）。
  2. 切项目：点左侧项目名即可，正文、检查结果、资料都会跟着换。没保存的正文会先自动保存，保存失败会拦着不让切走。
  3. 接着去「资料」页传招标文件。没有招标文件也能写，但不知道要响应什么，容易写空。

全部项目：归档、收进知识库、删除

点左上角全部（或项目名右侧的「···」），打开「全部项目」：能按名字搜，按「进行中 / 已完稿 / 已归档」筛，每本后面有四个动作。

  • 打开：点项目名直接切过去。
  • 收进知识库：把整本正文拼成一册，按章拆好存为「标书范例」，以后写别的项目可以照着结构写。没写正文的章节会跳过并列出来；重复收同一本只更新那一篇，不会产生同名副本。
  • 归档：只是从左侧列表收起来，正文、资料、检查记录、导出记录都原样保留，在「已归档」里点「取消归档」就回来。适合已经交出去、暂时不看的项目。
  • 删除：连正文、上传资料、检查记录、导出文件一起删，删完不能恢复。只有企业管理员能删，而且会确认两次。只是想从列表里收起来，用「归档」。
项目之间互不影响。想复用一个写好的目录结构，不用新建模板，正文页「沿用旧项目的目录」即可。
删除项目不影响知识库：你主动收进去的标书范例是公司资产，删项目不会带走它。要删范例请到「知识库」页删。

5. 资料

资料页管三件事：招标文件、本项目资料、知识库入口。

上传招标文件

支持 PDF / Word（.docx）/ Excel（.xlsx）/ CSV / TXT / Markdown，一次传一个文件。传完会解析出资格要求、技术参数、评分项、废标条款，写作和检查都以它为准。

  • 图片文件（.jpg / .png）本身不支持直接上传，请把图片放进 Word 或 PDF 再传，或直接把文字粘进对话框。
  • 扫描件 PDF：装了本地 OCR 才能读出文字，界面会提示「共几页、其中几页走 OCR」。纯图片页会被标成「未识别」，这些页里的要求不会自动进检查。
  • 只算真正读出来的字：页码标记、工作表名称、扫描占位提示都不算有效字数。纯扫描无 OCR、空文件、空工作簿、只有图片的 Word 都不会入库，会直接说清原因；也可以点「仅留存原件（待处理）」把文件留着，但它不进依据、不参与核查。
  • Word 内嵌图片目前不做 OCR：Word 里的文字和表格能读，图片里的文字、盖章、扫描件读不出来。有图片时会提示张数并标「待核对」，请把图片里的文字粘贴进正文或转成可复制的表格。PDF 扫描页在有本地 OCR 引擎时才识别。
  • 混合 PDF / 正文过少：已识别部分保留，未识别页号、OCR 页数、待核对原因会持久化，刷新后仍看得到。到「我提供的资料 → 解析待核对」可逐页补录，或对照原件后人工确认；补录或确认前，这份资料不作为依据，导出前会把它列为重点提醒。

上传本项目资料

业绩合同、资质证书、检测报告、人员简历、产品参数……传进来之后，写正文时会被自动取用，并在段落里标出来源。

查看与删除

每个文件都能展开查看摘要和页数，传错了直接删。删除只影响本项目，不影响知识库。

招标文件版本链

原文件、补遗、澄清、整份替换分开保存，不再用一个文本框盖掉旧版本。第一次上传或粘贴记为第 1 版；之后再传招标文件默认按「补遗」追加，原条款保留。到「我的资料 → 招标文件版本链」可以显式选补遗 / 澄清 / 整份替换并写文件名。

  • 补遗只改期限时，其他原条款、正文、证据都保留；旧自动要求按来源版本转失效，人工修订的行保留但标「新版待复核」。
  • 条款一变，之前逐条确认过的响应会降级为「待重新复核」，检查留痕与导出确认令牌一起失效；新版条款要重新体检、重新确认。
  • 删除或停用要求绑定来源版本，不会误伤新版条款；重复保存相同正文不会堆出多余版本。

逐条响应矩阵（招标要求表页）

要求不再只取前 24 条：全部要求都进有效范围，大纲用分批概览、逐章写作按章节相关度分配本批，界面写明「共几条、本批处理几条、未处理几条」。每条要求有稳定 ID、原文位置、来源版本与人工确认状态。

  • 词面命中或照抄要求只算候选；证据充分与人工复核分开记录。必需要求必须逐条确认落实，或标「不适用」并写明理由（记录责任人与时间）。
  • 页面上的百分比只是起草进度；即便过了 60%，只要还有必需项没落实，导出时仍会逐条列出提醒并给出补齐入口，但不会禁止下载。

要求表的删除（大项与小项）

三个分类（硬性要求 / 废标条款 / 评分项）是大项，下面每一条要求是小项，两类都能删：小项用行尾的「删除这一条」，大项用分组右上角的「删除这一组」（会连这一组的全部要求一起删掉），删前都会确认一次。每个分组也有「＋ 新增一条」，点它会选好分类并跳到新增框。删掉的大项不再留一个空分组；需要找回点「恢复被删要求」，或在那一组里重新新增一条。删小项时对应的逐条响应记录会一起清掉，不会留在检查口径里。

企业事实与原件附件

表达范例只学写法，不证明当前企业的金额或业绩。事实要写清实体、字段、数值、单位、适用范围、有效期、原件位置，并对照原件人工核验；拟承诺值由责任人确认，不写成历史事实。数值核对同时看实体、单位与含义，报价用 Decimal 按 ROUND_HALF_UP 保留两位小数核算小计与合计。

实际提交的原件可以上传并绑定事实 / 章节 / 资料 / 页码，从附件索引直接打开回跳。缺可核验事实会生成待补任务，写明应补的实体、单位与来源位置。

保护表单完成核验

投标函、报价、授权、承诺、资质、保证金这些章节不让 AI 改写，但照样核验：必填字段、占位符、有效期、报价总价关系、签章与证明附件。签章与资质有效期无法自动判定的，列「待人工复核」，由责任人按当前正文版本确认；正文一改，旧确认立即失效。短而完整的表单不套正文字数下限。

扫描件 PDF 先确认能识别出文字（页数下方会显示识别字数）。识别字数很低说明是纯图片，建议换一份文字版，否则写作和检查都会失真。

6. 知识库

知识库放两样东西：标书范例（写好的整本标书，写的时候照着它写）和通用素材（资质、业绩、承诺这类片段，写哪儿都能引用）。

两种类型

类型放什么系统怎么用
标书范例已经中标或写得好的整本标书、竞标书上传后按标题拆成章；写某一章时，直接取范例里同一章（例如「技术方案」）作参照，学它的层次、小标题拆法、句式和详略
通用素材公司简介、资质说明、售后承诺、技术亮点等片段按内容相关性检索，命中哪段引用哪段
范例里的事实（公司名、人名、金额、案例、证书编号）不会被照抄，只学写法；写作时用的还是你本项目资料里的真实数据。

上传一本范例

  1. 进「知识库」页，点上传标书 / 素材文件，选 Word / PDF / txt。
  2. 系统自动判断：能切出 3 个以上标准章节（投标函、商务、技术、报价、售后…）就按标书范例处理，并拆好章；否则归为通用素材。判断错了可以点「编辑」改类型。
  3. 范例卡片上会显示「5 章 / 16 节」这类统计，点看目录能看到拆出来的章节。
  4. 已经在本系统里写完的项目，不用再导出上传：在「全部项目」里点收进知识库，整本直接变成范例，卡片上会标「从项目成稿收录」。

写的时候怎么用上范例

  • 设为参照：在范例卡片上点一次，这本书就成为本项目「参照范例」，正文页顶部会显示书名。
  • 用它建目录：按范例的一级章节重建本项目的目录（只搬标题、不搬正文），相当于「按这本标书的格式来」。
  • 之后每生成一章，系统都会去这本书里找同名/相近的一章作参照；「查看本章依据」里能看到引用了范例的哪一章。

通用素材

  • 新增：「手动新增」，选「通用素材」，填标题和正文。
  • 筛选：顶部「标书范例 / 通用素材 / 全部」，后面带条数。
  • 编辑 / 删除：每条右侧展开后可改标题、改类型、改正文，或删除（删了不可恢复）。

7. 定目录

「标书正文」页左侧就是目录。目录不对，后面全白写，所以先把它定下来。

三种起点（空项目时三张卡片）

方式适合结果
按招标文件生成大纲新项目，招标文件已上传按评分项和章节要求生成 6～9 章
沿用旧项目的目录同类项目做过，结构可复用只搬标题，不搬正文
导入已有标书手上有半成品，想接着改按标题切章并替换当前目录

手动加章 / 改名 / 删章

  • 空项目时点「＋ 手动加一章」可以完全不用 AI，自己一章章把目录建起来；已有目录时，左侧「目录」标题右边的「＋ 加章」会在当前选中章后面插一章（不选就加到末尾）。
  • 鼠标停在目录某章上、或选中该章，右侧会出现 ✎ 和 ×：✎ 改名、× 删除。改名只改标题，正文、版本、依据、分工都跟着同一章走，不会把已写的内容弄丢；删除会连正文一起删，但删之前自动留整份目录快照，到「检查与交付 → 版本与回退」点「撤销本轮」可整份找回。
  • 同名标题会被拒绝（不少地方按章名找正文和依据），标题最多 120 字；名字里含「报价 / 投标函 / 承诺函 / 授权 / 资质」的新章会自动标成保护章节，AI 不改写。
  • 整本生成正在跑时不能改目录，会提示等任务结束，避免一边生成一边把章节挪走。

微调

  • 重新生成：右上角「更多」→ 生成大纲（会覆盖当前目录）。
  • 保护章节：报价表、投标函、承诺函这类会自动标记「保护」，AI 永不改写，需要你手工填。
  • 换目录可撤回：换完之后去「检查与交付」→「版本与回退」，点「撤销本轮」可整份恢复。

8. 写正文

左边目录选章，右边只编辑这一章。当前版本这一页只做定目录和写正文：团队协作、产出文件、投标包与暗标、长任务控制这些界面先不显示，避免一进来就被一堆暂时用不上的面板弄乱。下载 Word / Markdown 仍在页首，导出照样先检查；不符合只提醒、不禁止。

质量检查、整本体检、导出门禁这几套结论不用自己对照：「检查与交付」页最上面有一张能不能交卡，把结果汇成一句话（红 / 黄 / 绿）并给出下一步按钮，明细折叠在下面。

目录上的标记

  • 灰色序号 = 没写；绿色圆点 = 已有正文；棕黄底 = 生成中。

保存

自动保存：停手约 1.5 秒自动存入，右上角显示「已保存 09:12」。切章节、切页签前也会先存一次。手写大段内容时不用点保存。

生成期间你改了这一章

AI 生成 / 改写要几十秒。开始时系统记住章节版本，落库时版本对不上（说明你或同事改过），AI 稿不写入；编辑器上方会列出这份未采用的候选稿，看完再决定「用这份覆盖」或「丢弃」。不会报「已生成成功」却悄悄盖掉人工稿。

单章生成、单章改写、整本生成、导入标书、恢复快照共用一把项目写锁：前一个没结束，后一个会提示等待，不会两处同时改同一份正文。恢复快照会同步推进章节版本，另一个窗口拿旧版本保存会被拒绝。

顶部动作

  • 一键写整本：只写还空着的章节，已有的不覆盖；进度条会显示「正在生成 3/7：技术方案」。
  • 写剩下 N 章：中断后再点会接着写没写的部分。
  • 覆盖已有正文：在「更多」里勾选后才会重写已有章节，慎用。
生成中断（关页面、断网、模型超时）不会丢已写的章节，重新点按钮会跳过已完成的。

9. 检查与交付

检查只查硬伤，不能代替人工评审：逐条响应、数字有出处、无占位符、章节不空。

  1. 点开始检查，问题按章节列出来，可分「全部 / 未处理 / 高风险 / 已采纳」。
  2. 点单条右侧的去这一章改，直接跳到正文对应章节手工改。
  3. 要交给 AI 改就点采纳；不想动的点忽略。不采纳的，AI 一律不碰。
  4. 点按采纳的问题改好并复查，最多自动复查 2 轮，结果在「本轮改动与复查」里：改前 / 改后逐条对照。
  5. 改坏了不要紧：「版本与回退」里每次改写都留了快照，点撤销本轮按章恢复。

未达标章节

如果某章缺关键响应、有编造数字或占位符，会在导出前把这几章列成提醒，每行带按钮直接跳去改；提醒不会禁止下载。

检查没跑完 ≠ 通过

自检、章节状态、要求表、资料读取或结构核对出错，都会标成未完成并列出未检查范围，导出时会明确标成未完成，确认也不能代替重跑检查。状态分五种：通过 / 未通过 / 不适用 / 缺输入 / 运行出错；缺必需报价这类会列成「缺输入」，不显示「不适用」或「已通过」。

10. 导出 Word

  • 正文页右上角下载 Word：每次导出前都会重跑一遍检查，不吃旧结果；不符合项只作提醒。
  • 有高风险未处理 / 章节未达标时，会弹出完整的提醒清单，逐条写清差在哪。点仍然导出即可下载，也可以点先去修改回去改；不再要求逐条勾选，也不会把下载挡住。
  • 「更多」里还有下载 Markdown 和暗标导出（隐去公司名、签章等身份信息）。
「能不能交」卡是只读汇总，不会在你打开页面时把八项体检全部重跑一遍；真正下载时系统会再核一次。卡片只回答「现在能不能交」，点「仍然导出」属于知情确认，不等于检查通过。没做过体检、或正文改过导致上次结论过期，卡片都不会显示绿色。
检查不是形式：数字没出处、正文有「XXX / 待补充」这类占位符、章节空白，都会逐条列出来。现在这些只作提醒，不再禁止导出；导出的文件会记下这次提醒，提交前请务必人工逐项复核，避免交出去被判无效。

正式导出的四项必需检查（占位符与硬伤、废标条款、报价算术、暗标信息）在设置里取消不掉：关掉自动编排、清空可选能力后仍会执行，任一项跑不完会在导出前明确标成未完成，不会算作通过。任务卡把「实际写入 / 人工补稿 / 保护章节待人工 / 冲突 / 空稿」分开计数；整本生成跑完只叫正文已填写，质量、要求、附件与人工复核另有状态，不等于已可交付。收进知识库会留下这一版的内容指纹与核验状态，收录不等于已审核成稿。

产出文件与版本

检查与下载读的是同一份冻结快照（正文、有效要求、资料、策略、模板版本）。确认令牌绑这份快照：改正文、改要求、换资料、调策略或升级模板，旧确认立即失效。检查期间正文被改过会提示重新体检，不会发出「检查的是 A 版、下载的是 B 版」的文件。

Word / Markdown 都走同一道检查和最终文件检查（可打开性、占位符、内部标注、文档属性）。检查没过会先列出提醒，点「仍然导出」后照常发文件，并在产物里如实记下这次提醒；只有落盘登记失败才明确返回失败、不发文件。每份产物有独立 ID 和目录，同一秒导两次同名文件也不会互相覆盖；回下载会核对项目归属与内容摘要，磁盘文件被改过就拒绝。正文页底部的「产出文件」列出每份记录的版本号、当前定稿 / 历史版本、快照指纹与内容摘要，历史版本可下载但不会标成当前定稿。

基座能力生成的检查报告、修复稿、重排稿都是审阅件：文件名、下载说明和 HTML 内容里都会标明「未经导出门禁、未脱敏」，不能直接当正式投标文件提交。图片/嵌入对象里的身份信息无法自动检测，暗标项目需人工核对。

真实分册与投标包

正文页底部多了「真实分册与投标包」。它先给一份规划预览：按标题把章节归到资格 / 报价 / 商务 / 技术 / 其他，归错可以改每章的所属册，也能改册名。规划不是文件；不勾选「我已逐册核对」就点生成，后端会直接拒绝，前端和后端两道都挡。

确认后生成的是一个 zip：每册单独一份 Word、登记过且磁盘上仍存在的原件附件、分册索引、逐条响应表、文件包清单。每册都要过最终文件检查；有一册没过会列出提醒，确认后照常发包并把问题记进清单。投标包和 Word / Markdown 走同一道导出检查，不符合项只作提醒；确认令牌同样绑定冻结快照，正文一改旧确认就失效。

暗标规则与全包扫描

先登记本项目的企业全称、简称、人员、联系方式、地址；只勾开关、不填身份词不算配置完成。扫描读的是最终 .docx 二进制，覆盖正文、标题、表格、页眉页脚、脚注尾注、批注和文档属性，命中会写出在哪个部件。没登记项目规则时只做通用模式扫描，不会宣称完全暗标合规。「扫描当前 Word」是按当前正文临时渲染、不落盘、不登记产物，正式提交前仍要对最终文件再扫一遍。

字体字号、页边距、封面、页码、签章、命名与分册格式要对照招标文件人工核对，系统只报告文件里实际有什么。目录域由 Word 打开时更新（本系统不自动刷新域结果）；PDF 转换和电子投标客户端专用格式未实现；图片 / 嵌入对象里的文字、盖章、水印无法自动识别，须人工逐项核对。

产出文件 / 投标包 / 长任务控制（当前版本先收起）

正式产物与审阅件、历史版本下载、真实分册与暗标投标包、章节检查点与失败章重试，这些能力后端和接口都在、权限校验照常生效，但当前版本不在「标书正文」页显示：第一次用的人一进来看到这些容易乱，先把标书写完、检查过、导出跑顺，再决定它们该放在哪个页面。整本生成时页首进度条上仍有「取消生成」，取消后已写的章节不会丢。

要放回来：把前端 web/app.js 里的 SHOW_ADVANCED 改成 true，这几个面板就回到正文页底部；更推荐以后做成独立的「导出与交付」页签，两种都不用改后端。

项目团队与分工（当前版本先收起）

负责人、截止时间、定稿版本、章节分工与复核状态、成员与角色这些能力后端仍在、权限校验照常生效，但当前版本不在「标书正文」页显示，避免一进来就被一堆协作面板挡住主流程。先把标书写通、导出跑顺，再按需要把面板放回来。设置页的企业与成员管理不受影响。

补充规则（生效中，只是界面暂时不显示）：旧项目没有成员名册时，同企业账号默认可编辑；添加第一个成员后立刻切换为按名单授权，不在名册里的同企业账号连查看和下载都会被拒。只读人员改不了正文也下载不了文件，复核人员能标记复核但不能写正文；归档、删除、收录进知识库、恢复快照、改成员名册只有负责人或企业管理员能做。平台管理员与企业管理员分开，跨企业切换仍按登录账号所属企业。

模型与隐私

「设置」顶部的模型面板可以选模型、填 API Key、测连通性。关闭联网后不再调用外部模型，只用本地结果，内容零外发。身份证、银行账号、手机号会自动打码，报价表、投标函、资质章节正文永不外发。

多企业共用时配置会不会串

不会。项目数据本来就按企业分库，模型、密钥、预算、隐私、策略和运行状态也按企业各存一份。「设置 → 配置归属」会逐项写明是本企业配置、继承平台默认还是本企业尚未配置：策略类（隐私、预算、运行模式、智能体策略）在企业没保存过时继承平台默认，一保存就独立；模型与密钥绝不继承、绝不复制，连环境变量里的平台密钥也不会给其他企业，要各自录入。旧版本留下的公共配置已显式登记归属默认企业，升级后原样可用，不会被静默复制给别人。原件、上传件与导出产物也按企业目录分开，旧路径仍可读取。

备份、恢复与验收边界

在项目根用系统 python 执行 python -m backend.ops.backup create --out D:\backups 生成一份备份包，覆盖业务库（含各企业分库）、账号库、原件、上传件、导出产物、模型与策略配置，以及项目根 .env。数据库用 SQLite 一致性快照，不是直接复制 .db 文件——WAL 里还没落盘的写入不会被漏掉。verify 备份包.zip 逐个核对内容摘要与数据库完整性；drill 备份包.zip --report 报告.json 在系统临时目录做隔离恢复演练，开库对账后自动删除，不碰现有数据。

恢复（restore 备份包.zip --target D:\restore-test）只写空目录：写回生产数据目录、写进它的上下级、覆盖目标里已有的库都会被拒绝。演练通过只证明「备份能读回」，不等于业务验收通过；真实样本与业务人员独立复核必须由业务方自行完成，构造用例通过不能替代。备份包里有模型密钥和账号数据，按密钥管理存放，不要外发。多进程 / 多机 / 共享存储部署需要停机窗口或存储层快照，本脚本不覆盖这种场景。

附：新增核对项（2026-11-11）

下面几项是 2026-11-11 更新补上的。除「目录确认」会在写正文前多一步外，其余都默认收起、不增加主流程操作；目的是让「目录别白写」「解读完不用再翻原文」「该早点看见的风险早点看见」。更完整的说明见项目里 docs\使用手册.md。

目录确认闸门（写正文前多一步）

目录区右上角多了「确认目录」按钮。核对好章节名称与顺序后点一次，目录区显示「已确认」，这之后才能写正文。未确认时点「一键写整本」「AI 生成本章」「按资料改写」，或在对话里说「写整本标书」，都会提示先确认目录，避免目录不对整本返工。

改章节名、加章、删章、上下移、重新生成大纲、套用旧目录、导入已有标书，都会让确认立即失效，需要重新确认。升级前已经写过正文的老项目会自动视为已确认，不会被这次改动锁死。

章节行悬停时右侧有 ↑ ↓ 可微调顺序；只换顺序，正文、版本与依据都跟着同一章走。

企业资产台账（五分类）

「资料」页新增默认收起的「企业资产台账」卡：按资质证照 / 人员证书 / 业绩证明 / 检测报告 / 获奖荣誉五类登记，可填持证主体、证书编号、有效期、原件位置，并标记「我已对照原件核验」。资产属于企业、跨项目复用，原有的企业事实与项目资料一条都不迁移。

有效期沿用证照五态判定；系统不会 OCR 证书上的日期，也不给没填有效期的资产报警。过期资产会进导出提醒，但仍是「提醒 + 知情令牌可下载」，不是禁止下载。

得分材料反查（只列候选，不判得分）

「检查与交付」的能不能交卡多一行提示，点「查看缺件清单」可看评分 / 硬性条款与本企业资产的对照：哪条条款可能需要什么材料、现在有没有，分为「缺材料候选 / 材料过期待更新 / 有材料待核验 / 已有候选材料」。

它不判定「能得几分」，也不因为没匹配到关键词就说条款不需要材料。分值分配、原件真伪与评审口径都要人工对照评分办法确认；这行提示不改变能不能交的三态判定，也不禁止下载。

招标要素维度与 ★▲ 参数

「招标解读汇总」卡新增 22 项决策要素（保证金、开标时间、投标有效期、付款方式、质保期、合同条款、评标办法、废标条款等），命中时只切出原文片段并标出字符位置，没识别到一律写「未识别」，不补示例值。带 ★ / ▲ 的原文行单独成表，与货物清单分开列，两边数字不串；还按章节标题给出本章该重点核对的维度（默认折叠）。

招标解读汇总（资料页折叠卡）

「资料」页多了一个默认收起的汇总卡，展开时才计算，不拖慢首屏。它把招标要求（硬性 / 废标 / 评分各多少条）、评分要素、货物清单、最高限价、报价核对、证照状态、待核对资料聚成一张卡。评分要素总数报全量、明细只预览前几条；空项目如实说没有招标原文，不补示例数字。

这张卡不是已确认事实，卡上会写明「仍须对照原件核对」。它的用途是让你一眼看出哪一块没抽到，不能代替人工确认条款。

货物清单与最高限价

「资料」页另有默认收起的货物清单卡，预览物资名称、规格、单位、数量、分包、交货期。抽不到表头会如实说没识别到，漏数量会进导出提醒。最高限价只给四态结论：无 / 有金额 / 含糊 / 未提及；写「本项目无最高限价」就是「无」，不会被误读成金额，含糊时只提示人工核对。

报价核对新增限价与投标总价直接比大小，以及投标函、开标一览表、中文大写、多张报价表合计之间的交叉核对，结论逐条进导出提醒。它只说算术事实：含税价、单价限价、分包限价、角分剔除仍须按评审口径人工复核；没读到报价表就写「均未校验」，不用示例金额冒充通过。

真实国网文件里 ★/▲ 出现 0 次、* 全是乘号或尺寸、清单没有预算列。系统不会把 * 当强制参数，也不会编造预算列；如果招标文件确实带 ★/▲，会抽成独立的「★▲ 强制技术参数」表，只列原文行、不自动判定是否实质性响应，仍需人工核对。

证照有效期与临期预警

知识库新增/编辑素材时可选填「有效期」，卡片显示已过期 / 60 天内临期 / 有效 / 日期写错。已过期是高风险重点提醒，接进导出门禁，也会在「检查与交付」的能不能交卡上直接显示一行提示——不用等到下载前最后一刻才看见。临期与日期写错列为中等提醒。

系统不会 OCR 证书上的日期，也不会给没填有效期的素材报警，避免误判和噪音。证照扫描没跑完会如实说「没查成」，不静默当作没风险。这仍是「提醒 + 知情令牌可下载」，不是禁止下载。

导出提醒按评审后果分四级

提醒卡把结果归为硬性否决 / 硬性扣分 / 加分项 / 参考项，重点项和折叠明细各带标签，一眼能看出后果。原始清单和逐条确认口径不变，一条都没省略。

加分项恒为 0，并写明「系统不自动判定加分机会」——不硬凑一类让你误以为加分也查过了。

解析待核对里能看图片文字了

Word 内嵌图片的文字会用本地 OCR 摘出来，放在「解析待核对」里可展开查看，方便对照原件确认是不是漏了要求。这些字只供人工核对，绝不并入正文：二维码、界面截图里的字一旦混进正文，会污染按章检索、要求抽取和事实依据。有图片的文件仍标 needs_review、确认前不进依据池。

演示模式（未接模型）生成的是模板稿，整本结论一律红灯并写明「模板稿不能作为投标依据」；正文里的 XXX / 待补充 等占位符会原样保留，交给检查规则拦下，不会被导出清理悄悄抹掉。

12. 常见问题

说「验一下标书」却让我先上传，是坏了吗？

不是。项目里没有招标文件、也没有标书正文时，系统不会空跑——空跑出来的「0 个问题」会被误当成「没有废标风险」，所以它改为提示你先上传文件，或到「标书正文」按章填写内容。放进内容后再发同一句话即可。

只上传了招标文件，也提示「缺标书正文」？

废标风险要两边对照：招标文件抽否决条款，投标正文逐条比对。只有一边时，系统会跑能跑的部分，并在回复开头注明「缺什么、结论只覆盖哪一半」，不会给你一个完整的假结论。

点了「一键写整本」没反应？

看左侧目录是否为空（要先生成大纲）；看目录区是不是还没点「确认目录」（没确认会明确提示，点一次即可）；看是否所有章节都已有正文（要重写需先勾「覆盖已有正文」）；剩下只有保护章节时，需要手工填。

生成很慢 / 中途停了？

整本生成是逐章调用模型，章节多就要几分钟。中途停了再点一次会从没写的那章接着来，已写的不会丢。同一个项目同时只允许一个写任务：连点两下不会起两个，页面会提示「已接上原任务」。

任务显示「部分完成」是什么意思？

表示有章节没真正写进去，任务卡里会分开列：模型没返回（多为超时或思考型模型把额度用完）、生成期间被你改过（保留你的版本，不覆盖）、出错、未达交付标准。只有真正落库的章节才算「已写」，对照清单单独重试那几章即可。

能取消整本生成吗？取消后会发生什么？

能。任务卡上点「取消生成」。取消在章节边界生效：后续章节不再调用模型、不再写正文，都会记为「已取消」留在检查点里。已经在模型端跑着的请求会算完，但结果返回后不会写进标书；取消不等于撤销远端计算，也不退还在途请求。「长任务控制」里能看每章的检查点状态，点「重试失败章」只重跑失败 / 空稿 / 取消的章节，「恢复中断任务」从检查点接着跑。

服务重启后任务还在跑吗？人工新稿会被覆盖吗？

不会假装还在跑。重启收尾会把上一进程遗留的排队 / 运行任务标成已中断、可恢复，并保留章节检查点，也不会挡住新任务。恢复按章节版本核对：任务开始后你手写或改过的章节一律标「保留人工稿」，不会被模型稿覆盖。当前后台是单进程单线程池 + 进程内互斥锁，只能保证同一进程内同项目不并发写；多进程 / 多机部署前需要跨进程任务认领或分布式锁，这一步尚未实现，不能靠多开进程直接扩容。排队时长是实测的，可在任务接口里看并发建议。

双击启动文件闪一下就没了？

现在启动前会先跑一遍自检，把 Python 版本、依赖、数据目录、端口占用、OCR、模型状态逐项打印出来，并给出「怎么办」。按提示处理后再双击；自检不通过时窗口会停住不会闪退。自检会打印当前 Python 解释器的完整路径，装依赖请用同一个解释器执行 python -m pip install -r backend/requirements.txt。

数据目录和端口在哪里改？

只改 .env 里的 BIDAGENT_DATA / BIDAGENT_HOST / BIDAGENT_PORT 即可：主库、账号库、基座库、策略、输出、原件与缓存都会落到同一目录，自检、启动文件和真实服务用同一个地址，不再各写一份。相对路径按项目根解析；命令行里直接设的真实环境变量优先于 .env。端口被占用时自检会直接阻断并给出改法，不会说「可以启动」却起不来。模型那一项会把「配置齐全」和「已验证可连通」分开显示：配置齐全不代表能调通，首次生成前请在「接入模型 → 测试连接」确认。

这里统一的是环境隔离（一台机器的数据与端口）。多企业共享部署时，模型、密钥、预算、策略与权限仍需按企业分别配置，不能把路径统一当成企业隔离已完成。

项目越建越多，左侧列表放不下？

左侧只显示最近 8 个，多出来的点「全部」进「全部项目」：可以按名字搜、按状态筛（进行中 / 已完稿 / 已归档）。已经交出去的项目点归档，就会从左侧收起来，数据一条不动，需要时在「已归档」里点「取消归档」。

删除项目和归档有什么区别？

归档只是收起来，随时能恢复；删除会连同正文、上传资料、检查记录和导出文件一起删掉，不能恢复。删除只有企业管理员能做，并且要点两次确认。只想从列表里清走，请用归档。

写完的标书能留着当模板吗？

能。在「全部项目」里点收进知识库，整本会按章拆好存成「标书范例」，以后写别的项目就照着它的结构写。收过的那本按钮会变成「更新知识库」，改了正文再点一次即可，不会多出副本。

下载时弹出的检查提醒会挡住导出吗？

不会。高风险问题没处理、章节没达标、有占位符都会列出来，但只是提醒：点「仍然导出」就能下载，想先改完再导也行。文件会记下这次提醒，提交前请人工复核。

数据和别人会混吗？

不会。每个企业一套独立数据库，登录后自动切到本企业的库；跨企业访问接口会直接拒绝。

换电脑还能接着写吗？

能，用同一个账号登录即可，项目和对话都存在服务端。上次改到哪一章也会记住。

想换个目录结构，正文会丢吗？

同名标题的正文会保留，其他会留在快照里。换完可在「版本与回退」整份撤销。

数据怎么备份、怎么搬到另一台机器？

用 python -m backend.ops.backup create 打包，再用 drill 演练一次；要迁机器就在新机器的空目录用 restore 恢复，把 BIDAGENT_DATA 指到恢复出来的 data 目录启动。脚本不会自动覆盖现有数据，见第 11 节。

能离线用吗？

系统本身跑在本机/公司内网；不接模型也能写（质量会差一些），内容零外发。

生成输入与逐要求支撑（2026-11-14）

在“标书正文”点击“来源与历史”，查看当前稿对应的实际输入、截断片段及历史尝试。输入来源只证明模型看过什么，范例与召回候选不能自动证明正文正确；原文变化会标记，无法定位的输入块不伪造坐标。

在“管理 → 招标要求表 → 逐条响应矩阵”点击“核对本条事实 / 证据 / 附件”：先保存要求类型、主体、字段、单位、范围及开标或评审日期，再为本条选择事实、原文证据或附件。关系可登记为候选、支持或冲突，也可解除。“生成候选关联”只提供建议。

原件类先关联有效附件，再人工核对原件字段与签章并保存勾选。更换文件或关联后必须重新核验。缺口处理完才能人工确认；照抄条款、缺证明或错误归属不能凭点击绕过。不适用需明确理由与责任人。

确认绑定具体版本。正文、要求、事实、原文或附件变化后返回待复核，导出会再次核对材料内容。人工改稿后保留旧来源并待复核；历史恢复只使用匹配记录，没有记录则显示来源未知。段落优化无法可靠划分影响范围时保守标待复核。

旧项目无指纹的确认进入待复核，正文和原复核信息保留。关系写操作需要项目负责人、复核人或企业管理员权限；企业间输入记录与材料不共享。

原件自动打开检查支持 PDF、DOCX/XLSX/PPTX、ZIP、常见图片和 UTF-8 文本。损坏、空文件或未知格式需要补充可核验文件。文件可打开不等于签章和业务适用性已经通过。
